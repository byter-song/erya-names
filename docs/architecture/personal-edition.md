# 个人版 0.3 的实现契约

## 选名记录

`inbox` 是浏览过的灵感，不计入方案的候选数量。`favorite`、`comparison`、`finalist` 才属于用户保留的候选。`rejected` 是可恢复的暂不考虑状态，保存原因。数据库 v3 和备份 v2 继续使用原有枚举，避免破坏既有方案。

生成、筛选、读解释、收入候选在 `/projects/:id/generate` 完成。`/candidates` 只是兼容重定向。侧栏条件入口跳到可展开的同页条件编辑器。修改条件只影响后续生成，不重写既有名字。

## 内容包

个人包的字符与典故为 `source_checked`，与原有生产人审 `verified` 明确分离。`modernCombinations` 是个人包可选集合，每项包含组合名、独立整名取意、1–2 个风格、实际使用提醒和表达倾向；名字本身必须通过同一套规范字、家庭条件与语言规则。

现代组合只作为编辑推荐，没有伪造的古籍引用。组合取意写入候选 summary，使用提醒写入同一候选的 sourceEvidence，既有备份结构可完整保存。所选五行只参与软排序，不能绕过硬条件。

`data:build-personal` 从仓内来源资料重建个人包，`data:audit` 检查哈希、用字、引用和许可；`quality:combinations` 对全部 500 个组合逐一调用真实生成器，核对名字、整名解释和使用提醒。

## 计算与性能

组合生成按固定种子遍历和抽样，避免构建所有两两组合的富对象数组。全名去重和历史排除在应用层执行；持久化事务内再检查一次指纹，防止两个窗口从相同历史生成后重复写入。

语料作为同源、带内容哈希的 JSON 发布。应用先加载并校验资料结构，再初始化路由；资料失败时保留重试与已有方案/备份入口，暂停生成。页面按路由按需加载；民俗历法计算随相关页面加载，避免首屏下载无关代码。

## 保存与导出

完整建档在单事务写入，评分与备注按操作顺序持久化，避免前一次保存覆盖新内容。候选详情使用可关闭、焦点可恢复的模态框。打印报告不直接展示内部规则 ID；隐藏出生信息时同时隐藏四柱等派生出生资料。

## 民俗口径

中国标准时间 UTC+8；公历 1900–2100；不做真太阳时或历史夏令时修正。可选午夜/晚子时换日，时辰不详时只显示三柱。表层五行计数、藏干、纳音和名字字义意象分开展示，避免混算。五格只按明确笔画演算公式，不输出吉凶或人生预测。

## 挥毫开卷环境

环境层不加载山水图片，由 CSS 宣纸纹理、云线、圆轨、静态墨色和一次性横向笔触构成。应用挂载后不注册视觉用途的 `pointermove` 或 `pointerdown` 监听，不渲染持续 Canvas，也不提供动效开关。

启动阶段显示“展卷寻名”结构，数据和应用代码准备完成后由 React 根节点替换；正常模式保证最短约 650ms 的单次挥毫展示，`prefers-reduced-motion` 下不增加等待并直接显示完成态。屏幕品牌字和大标题使用仓内裁剪版 Ma Shan Zheng，正文与打印继续使用系统字体。

视觉提供两套主题：亮色“雾青宣纸”和暗色“挥毫开卷”。首次进入按 `prefers-color-scheme` 选择，用户通过太阳/月亮图标手动切换后写入 `localStorage` 的 `erya-names:theme`。主题仅改变设计令牌与表面色，不影响数据、路由和打印；侧栏导航不触发路由级页面进入动画。
